Lexical search that finds the exact word, symbol or phrase

with BM25 relevance ranking that matches exactly where it matters that forgives typos and fragments in 12 kB of gzipped JavaScript with zero runtime dependencies in your browser and Node.js

defuss-lexicalsearch indexes your documents field by field and answers keyword, phrase, prefix, typo and literal queries while you type. Exact-first ranking puts the literal match on top, and field-weighted BM25 orders everything after it. Indexing and search never touch the network.

Exact where it matters

Literal modes compare the original strings: e.g. C++ never matches C#, and operator == never matches operator !=. Exact-first ranking keeps a whole-field match above every partial one, whatever the corpus statistics say.

Ranked like a search engine

Field-weighted BM25 with an analyzer per field and derived fields, so one symbol can be a raw keyword and a set of code words at once. With exact-first ranking, results come in strict tiers: literal, keyword, identifier-prefix, term, partial, fuzzy and incomplete.

Forgiving input

Prefix completion, suffix and inside-word matching, Levenshtein or transposition-aware typos, completion despite a typo (Kül finds Kühlschrank), quoted phrases, AND and OR, field restrictions and exclusions. Every expansion is exact: no cap silently drops a match.

Small enough to ship

The core is 12 kB of gzipped JavaScript with zero runtime dependencies, as ESM and CommonJS with TypeScript types. An index serializes to a JSON snapshot and restores with every structure rebuilt.

Private by design

Indexing and search run in your browser tab or Node.js process: documents and queries never leave the device, and no third party ever sees them. Only fromURL fetches, and only when you call it.

Many languages, many kinds of text

Unicode words, code identifiers, raw keywords and whitespace symbols, plus analyzers for 20 languages: Snowball stemming for 13, word segmentation for Japanese, Chinese and Thai, n-grams for Korean, Bangla and Urdu, and tone folding for Vietnamese.

      How it works

      Analyze once, then match and rank every query

      Each field runs its own analyzer into postings with word positions and a vocabulary trie. A query is parsed into words and quoted phrases, analyzed the same way, expanded where you asked for it, and ranked by BM25; with exact-first ranking, the tier decides first.

      Exact-first tiers, strongest first

      With exact-first ranking, the weakest clause of a result decides its tier. A literal match always outranks a keyword match, however rare the words of the other result are; BM25 orders results within one tier.

      1. literal the whole original field equals the query, whitespace included
      2. keyword an exact analyzed keyword, such as a case-folded identifier
      3. identifier-prefix a keyword starts or ends with the query
      4. term the analyzed words of the query occur exactly
      5. partial a word starts with, ends with or contains the query
      6. fuzzy a word lies within the edit distance, or starts within it while you type
      7. incomplete under OR, at least one query word is missing
